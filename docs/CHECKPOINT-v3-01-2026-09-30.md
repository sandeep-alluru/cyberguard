## 4. Base SFT corpus — a real defect found **outside** the review, and fixed

Dataset prep ("cleaning") covered duplicate removal, null/empty checks, contamination scans and
offensive-framing review. It **never** covered secret hygiene, and `cybersec-reasoning-merged` is a
hardcoded-credential / CVE corpus that legitimately embeds key material. Measured:

| file | rows | rows changed | patterns removed |
|---|---|---|---|
| `sft/merged.jsonl` | 23,146 | 159 | 279 Google API keys, 122 AWS key ids, 62 AWS secret literals, 13 literal secret assignments, 8 PEM private-key blocks |
| `sft/fenrir.jsonl` | 99,730 | 6 | 2 GitHub PATs, 6 bearer tokens |
| `sft/primus.jsonl` | 4,891 | 0 | — |

Fix: `tools/redact_secrets.py` replaces only the secret **value** with a typed placeholder, keeping
the CWE-798 lesson and the surrounding analysis. Structural markers used by detection rules (a YARA
`$a = "-----BEGIN RSA PRIVATE KEY-----"` definition, `$AWS_SECRET_ACCESS_KEY` references,
`your_key_here` placeholders) are deliberately **not** treated as credentials — that is the
difference between 282 rows a naive scan flags and 165 rows actually changed.

**Verification after the pass:** re-scan finds **0** value-bearing patterns; row counts unchanged
(99,730 / 23,146 / 4,891 = **127,767**); every line parses as JSON (0 bad). Receipt:
`data/v3/REDACTION-RECEIPT.json` (counts and paths only — no secret value and no hash of one).
