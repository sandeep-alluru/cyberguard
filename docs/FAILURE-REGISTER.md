## F. WHERE WE KEEP GOING WRONG — the patterns

Nineteen reporting errors and twenty-four code defects is not bad luck. They cluster:

**Pattern 1 — I verify the artifact I wrote, not the artifact that exists.**
B1 (parser), B6 (cap hits), B9 (empty populations), B10 (partial intersections) were all *my code passing my own test*. C9/C10 came from reading my own summary instead of re-counting. **A self-written test cannot catch a self-written misconception.**

**Pattern 2 — I read a filename, a config, or an intention instead of the data.**
A2 (`no-trail` that had trails), A8 (config epochs 1.0 vs completed 0.205), B15 (assumed a generation default existed), C3 (training trails treated as generated tokens), **A9 (a split's *construction* read as a property of the corpus — "held out by construction" was true of Trendyol and was assumed to extend to a source added later by a different route)**. **Labels and configs are claims; the rows are the evidence.**

**Pattern 3 — I compare things that are not comparable.**
C2 (CDT against UTC), C13 (different completed epochs called "identical recipe"), C14/C15 (different selected subsets), C7 (a paper cited by a title it doesn't have), **A10 (the held-out answers compared RAWLY, across two files whose JSON escaping depth differs — the held-out file keeps the Trendyol reference's own escaping, the SFT file restores literal `\n` to real newlines, so 474 identical answers were reported as different and the published figure said 25 when it is 499)**. **Every one was a units, subset, identity or encoding error.**

**Pattern 4 — I answer the question I can measure, not the question asked.**
C1 (counted a broader predicate than defined), C3 (measured the wrong token population), C5 (measured token length when the question was decoded text). **The measurement drifted from the construct and nobody noticed because the number looked plausible.**

**Pattern 5 — I report progress instead of doing the work.**
FR-D2 (fifteen rounds of watchdog reports), C16 (planning-as-execution). The harness's own words apply: *"Directives that live only in prose are followed only while someone is watching."*

**Pattern 6 — I narrow the failure to something fixable and move on.**
A4 (audit failed → training ran), FR-D4 (blank human check accepted). Both were *known* and both proceeded, because the record didn't mechanically block them.

**Pattern 7 — the supervisor was checking the design while the machine was unobserved.**
The zombie `cti_eval.py` holding half the GPU for 12.5 h producing 0.0000 was found by chasing a 7× throughput gap — not by review. **Design review does not inspect the machine.**
