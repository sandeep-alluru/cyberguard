# Staging readiness — CyberGuard v3 (2026-09-30)

tools/stage-v3.sh prepares the post-approval transfer of the confirmed v3 training inputs to
spark-40ee. It follows stage-v2-arms.sh, including that script's recorded lesson (CRAFT-O-05):
transfer ONE file at a time and verify the remote sha256 against the local value, because a
multi-path transfer can silently move nothing while appearing to succeed. Any mismatch aborts.

Safety properties:
  - DRY RUN BY DEFAULT; the host is read-only until Sandeep approves training, so --execute is
    required before a single byte is written.
  - refuses to stage while a trainer is live on the host, using the same exact-argv guard
    run-v2-arm.sh uses (a substring scan would match any shell merely naming the file).
  - verifies BOTH sha256 and row count on the host after each file, not just exit status.
