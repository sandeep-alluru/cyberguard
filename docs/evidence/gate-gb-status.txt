# G-B triage — the ranking metric is not a repair, it is an unmeasurable spec (rev 11)

Review cycle 3 finding 4: the cited gate computes (TPR+TNR)/2 from one hard-label confusion matrix,
not the ROC-AUC >=0.95 ranking score PLAN sections 8.5/8.9 require. Independently reproduced, and then
taken one step further -- the reason is structural, not laziness in the evaluator:

1. The instrument ASKS FOR A HARD LABEL. Probe prompts are:
     'Classify as _malicious_ or _benign_. One word only.'
     'Verdict (one word: malicious or benign):'
   A one-word-answer battery cannot yield the per-item continuous scores a ROC curve needs.

2. The battery OUTPUT CONTRACT has no score field. Checked every stored G-B output:
     research-tmp/f15/battery-gB-base.json
     research-tmp/stub-evals/battery-gB-{base,armA,armB}.json
     research-tmp/codex-evalchain-stub-evals/battery-gB-{base,armA,armB}.json
   -> 'has score/prob/logit/confidence field: False' for all of them.

3. The cited gate says so itself, in the code:
     'A single operating point cannot give a ROC curve, so the hard-label AUC is the balanced
      accuracy (tpr+tnr)/2 and it is REPORTED AS SUCH ... inventing an AUC would be worse than
      declaring one.'

Therefore ROC-AUC >=0.95 cannot be produced from any existing artifact. Producing it requires
re-designing the probe prompts to elicit calibrated scores AND a new 300-probe generation pass per
arm -- i.e. new machinery for a second metric on a gate whose operational question is already
answered by the measured operating point.

OWNER DECISION (flagged, not decided):
  (a) KEEP the hard-label operating point -- precision >=0.90 at FPR <=5%, with support
      n>=300 / neg>=200 / pos>=100. Measurable now from data that already exists, and it is the
      decision-relevant question for a triage gate. [RECOMMENDED under the over-engineering
      directive: a ranking metric that needs a new instrument must justify what decision it changes.]
  (b) BUILD the ranking instrument (new prompts + regenerated battery) to obtain the AUC.

Until the owner chooses, G-B stays an OPEN evaluation blocker and no ROC-AUC is claimed.
