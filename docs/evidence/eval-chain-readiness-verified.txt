# Eval-chain readiness — verified end-to-end, and a crash found and fixed (rev 11)

Purpose: prove the post-training scoring path works BEFORE the adapter exists, so that when training
completes the run is a known-good sequence rather than a first attempt (the same approach used for
tools/stage-v3.sh). Executed with --stub, so no GPU and no model.

## BUG FOUND AND FIXED: v2/assemble_gate_inputs.py crashed with UnboundLocalError: roles
   'roles' was created INSIDE the 'if bat:' block (battery receipts present) but read unconditionally
   at A['instrument_roles'] = roles. With NO battery receipts -- e.g. invoked without --extra-evals,
   or a first pass before any battery has run -- the assembler died and the eval chain stopped.
   Reproduced, then fixed by initialising roles before the conditional block. The bat-true path is
   byte-identical; the bat-false path now yields empty role lists instead of crashing.
   Verified: the exact command that raised UnboundLocalError now exits 0.

## THE SEAM (this was wrong on my first attempt and is worth pinning)
   The gates consume 'gate-inputs-*.json' from the evals directory. The assembler must therefore be
   pointed AT that directory, and the battery receipts passed via --extra-evals:

     1) python3 v2/run_battery.py --battery <B> --arm <base|armA|armB> --out EVALS
     2) python3 v2/assemble_gate_inputs.py --extra-evals EVALS --out EVALS
     3) python3 v2/gates_v2.py --evals EVALS --out REPORT.json

   My first attempt wrote the assembler output to a separate directory, so the gates found no arm
   inputs and silently reported arms_found: [] with everything UNMEASURED -- a fail-closed outcome
   that LOOKS like a legitimate 'no data' verdict rather than a wiring mistake. That is the trap:
   a wrong invocation is indistinguishable from an empty measurement unless arms_found is checked.
   ALWAYS assert arms_found is non-empty before reading a verdict.
