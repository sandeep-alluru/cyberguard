## The one genuinely blocked gate — confirmed against the data, not just the prose

§8.9 declares **G-D `STATUS: BLOCKED`** because the pinned documents carry no gold span labels.
Verified on `v2/candidates/arcspan-train-sample.jsonl` (500 rows, keys `labels`/`source`/`text`):

- rows with **non-empty** labels: **0**
- rows with **empty-string** labels: **500**

So the plan's blocked status is accurate, and the plan already states the consequence correctly:
until the receipted human-authored labels bundle exists, G-D **cannot pass** and empty `labels` fields
must never be treated as verified empty gold answers. This is a **blocked measurement, not a missing
scorer** — the scorer exists; the reference does not.

## What this changes

Nothing about the launch decision: the eval chain runs post-hoc, and G-D's blocker is already recorded
in the plan with its disposition (NO-SHIP for that gate until the labels exist). What it changes is
confidence in the readiness claim: the only instrument that was specified-but-absent (§8.1) is now
implemented and acceptance-passing, and no other gate is in that state.
