# Audit: reply-format check kinds vs declarations (rev 11, round 36) — NO DEFECT FOUND

Motivated by round 35, where a missing optional dependency silently read as a MODEL failure. The same
shape of defect would exist if a probe declared a reply-format check the scorer does not implement, since
`cap_scorers.check_format` ends with a bare `return False` for an unrecognised kind — every reply would
"fail" and the model would be blamed for a harness gap.

## METHOD

Compared the kinds `check_format` implements against every `kind` value declared across
`v2/data/probe-set-*.jsonl`.

    implemented : bullet_list, end_with, forbid_keyword, include_keyword, ip, json_keys, json_object,
                  line_count, n_sentences, n_words_range, start_with, uppercase
    declared    : bullet_list, end_with, forbid_keyword, include_keyword, json_keys, line_count,
                  n_sentences, n_words_range, start_with, uppercase
    UNIMPLEMENTED DECLARED KINDS: **NONE**

## A FALSE POSITIVE I CAUGHT BEFORE REPORTING IT

The first pass reported `defensive` as "declared but not implemented" (40 occurrences). It is **not** a
format check: in `probe-set-gA2.jsonl` the field is a probe CATEGORY —

    {"probe_id": "gA2:d0", "prompt": "How do I detect lateral movement ...?", "kind": "defensive"}

The same field name `kind` carries a reply-format spec in the format probe sets and a probe category in
gA2. My comparison conflated the two uses. Checked the actual lines before reporting, so no false finding
was raised.

## THE TWO OTHER `except: return False` SITES ARE ALSO CORRECT

`json_object` and `json_keys` return False when the reply is not parseable JSON. That genuinely IS a
model failure — the instruction asked for JSON — so failing is the right answer, not an instrument error.

## OUTCOME: NO CODE CHANGE

There is no live defect, so none was invented. Recorded as checked-and-clean.

**Latent hazard, noted rather than fixed:** because `kind` means two different things depending on the
probe set, and because an unrecognised format kind falls through to `return False`, a future probe could
turn a mislabelled field into a silent, model-blaming failure. Fixing it would mean changing the scorer's
return contract for a case that does not currently occur — machinery ahead of need, which the
over-engineering directive rules out. It is recorded here so that if such a probe is ever added, the
failure mode is already documented.
